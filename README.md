# MailSort - автоматизированная сортировка корпоративной почты

Система читает входящие письма из файловой системы, классифицирует их по
смысловым категориям, раскладывает по папкам и формирует лог и статистику
обработки.

## Основные функции проекта

1. **Чтение** все файлы из папки `data/inbox/` (письма в виде текстовых файлов,
   а также файлы неожиданных форматов: `.json`, `.bin`, `.jpeg`, файлы без
   расширения, пустые и повреждённые файлы).
2. **Классифицирование** каждого письма по ключевым словам в теме и теле письма.
3. **Перемещение** файлов в папку соответствующей категории внутри
   `data/processed/`.
4. **Логирование** хода работы в консоль и в файл `logs/run.log`.
5. **Вывод статистики**: сколько писем попало в каждую категорию и сколько
   файлов оказались проблемными.

## Категории

`incidents` - критические инциденты, сбои, «срочно», «не работает»
`requests_for_equipment` - заявки на технику: ремонт, замена, ноутбук, принтер
`access_rights` - доступы и права
`hr` - кадровые вопросы: новый сотрудник, отпуск, больничный
`monitoring` - автоматические уведомления систем мониторинга
`contracts` - счета, акты, договоры, документы
`technical_problems` - проблемы с ПО: не запускается, зависает
`meetings_communications` - встречи, созвоны, дайджесты
`spam_phishing` - спам и фишинг
`client_partner_requests` - обращения внешних клиентов и партнёров
`undefined` - письмо не подошло ни под одно правило
`unreadable` - файл не удалось прочитать (пустой/повреждённый)

## Дополнительно

Две последние категории служат для сортировки писем,
которые не попадает ни в одну категорию. Любой тип данный так или иначе отсортируется, а приложение не упадет.

Чтобы добавить новый тип ключевых слов, достаточно
дополнить словарь `CATEGORIES` в `src/config.py`

## Требования
- Python 3.10+
- Для запуска тестов - pytest (см. `requirements.txt`)

## Установка

- Клонировать репозиторий
- Создать виртуальное окружение(необязательно)
- pip install -r requirements.txt

## Запуск

Положите письма в папку `data/inbox/`, затем запустите приложение.

### macOS / Linux

Через bash-скрипт (рекомендуется):
```bash
bash run.sh
```

Или напрямую:
```bash
python3 -m src.main --inbox data/inbox --out data/processed --log logs/run.log
```

### Windows

В **Git Bash** аналогично (рекомендуется):
```bash
bash run.sh
```

В **PowerShell/cmd** можно запустить аналогично:
```powershell
py -m src.main --inbox data/inbox --out data/processed --log logs/run.log
```

### Примечание
**Про `py` и `python3`.** В Windows стандартный лаунчер - `py`, в macOS/Linux -
`python3`. Скрипт `run.sh` сам определяет, какой интерпретатор доступен,
поэтому **переписывать код под конкретную ОС не
нужно**. При необходимости интерпретатор можно задать вручную(см. комментари к run.sh)

### Аргументы командной строки

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--inbox` | `data/inbox` | папка с входящими письмами |
| `--out` | `data/processed` | папка для разложенных писем |
| `--log` | (нет) | путь к лог-файлу; без него лог идёт только в консоль |

## Тесты

```bash
# macOS / Linux
python3 -m pytest

# Windows
py -m pytest
```

Тесты не зависят от содержимого `data/inbox/` - они используют собственные
данные (фикстуры из `tests/conftest.py` и временные файлы через `tmpdir`).

## Структура проекта

Данные проходят через линейный пайплайн: 
чтение -> классификация -> перемещение -> сборстатистики. 
На каждом шаге за работу отвечает отдельный модуль, что упрощает
тестирование и расширение.

```
hackathon_tp/
├── data/
│   ├── inbox/            # входящие письма (на вход)
│   └── processed/        # разложенные по категориям письма (на выход)
├── logs/                 # лог-файлы работы (создаётся при запуске)
├── src/
│   ├── config.py         # категории и ключевые слова
│   ├── models.py         # модель данных Email
│   ├── email_reader.py   # чтение и парсинг писем
│   ├── classifier.py     # классификация по ключевым словам
│   ├── file_organizer.py # перемещение файлов по папкам
│   ├── stats.py          # сбор статистики
│   ├── logger.py         # настройка логирования
│   └── main.py           # точка входа
├── tests/                # тесты (pytest)
├── run.sh                # bash-скрипт запуска
├── requirements.txt
├── .gitignore
└── README.md
```

## Возможные проблемы

- **`./run.sh: Permission denied`** - сделайте скрипт исполняемым: `chmod +x run.sh`.
- **`No module named src`** - запускайте из корня проекта (там, где лежит папка `src`).
- **`No module named pytest`** - установите зависимости: `pip install -r requirements.txt`.
